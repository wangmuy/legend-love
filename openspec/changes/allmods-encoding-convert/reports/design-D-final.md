# D 方案定稿：hint（带前缀 + 全局 index）+ 旁路表 + 存档覆盖表

> 最终决策（用户确认）：
> - **Q-A**：hint **带类别前缀**（便于 UPedit 中辨识人/物/武功等类别）
> - **Q-B**：旁路表**带 index 列**，该 index 直接作为 hint 内容 → 全局唯一主键
> - **Q-C**：旁路表**按段分组**（便于人工查阅）

## 1. Hint 格式（带前缀 + 段内 `%04d`）

每个字段的 hint 由「类别前缀 + **段内** index」组成。
**index 每段从 0000 开始**（不是全局自增）。

| 字段 | 宽度 | 前缀 | hint 格式 | 段内 index 上界 | 最长实例 | 含 NUL | 结果 |
|------|-----|------|----------|---------------|---------|-------|------|
| Person.姓名 | 10 | `P` | `P%04d` | 1600 | `P1599` (5) | 6 | ✅ 余 4 |
| Person.外号 | 10 | `N` | `N%04d` | 1600 | `N1599` (5) | 6 | ✅ 余 4 |
| Thing.名 | 20 | `T` | `T%04d` | 1650 | `T1649` (5) | 6 | ✅ 余 14 |
| Thing.名2 | 20 | `T2` | `T2%04d` | 1650 | `T21649` (6) | 7 | ✅ 余 13 |
| Thing.说明 | 30 | `TD` | `TD%04d` | 1650 | `TD1649` (6) | 7 | ✅ 余 23 |
| Scene.名称 | 10 | `S` | `S%04d` | 153 | `S0152` (5) | 6 | ✅ 余 4 |
| Wugong.名称 | 10 | `W` | `W%04d` | 398 | `W0397` (5) | 6 | ✅ 余 4 |

**UPedit 里一眼可辨：**

```
人物 1:  姓名 = P0002    外号 = N0003
物品 0:  名 = T0005      名2 = T20006   说明 = TD0007
场景 0:  名称 = S0008
武功 0:  名称 = W0009
```

### 为什么用段内 index（而非全局）

**关键洞察：hint 已带前缀，前缀本身已经区分了段。** 所以段内 index 与全局 index
在唯一性上**完全等价**：

```
全局 index:  P0002, T0005, W0009   (跨段连续 0..3800)
段内 index:  P0002, T0005, W0009   (每段从 0 开始)
-> hint 上完全一样，都唯一
```

段内 index 的优势：

| 维度 | 全局 index | 段内 index |
|------|-----------|-----------|
| hint 唯一性 | ✅ | ✅（前缀已区分） |
| 当前上界 | 3787 | **1650**（更宽裕） |
| 未来余量 | 9999/6 ≈ 1666 条记录就爆 | 9999/3 = 3333 条记录（Thing 最坏） |
| `rN.ovr` 可读性 | `0000=郭靖`（需查表才知段） | **`P0000=郭靖`**（自带段信息） |
| 与按段分组的表 | 不匹配 | **自然匹配** |

> **未来余量是决定性因素**：若某 MOD 记录数增长到 3 倍，全局 index = 11403 **溢出**，
> 而段内 index 最坏（Thing）4950 **仍然安全**。

**实测（全 20 MOD，36873 个字段）：0 溢出；段内 index 最大 1649，全局累计最大 3787。**
> 建议构建期断言：每段 `index <= 9999`。

## 2. 旁路表格式（按段分组 + index 列）

```lua
-- mods/mingdong/data/ranger.str
-- 格式: index,类别,记录下标,字段,值(UTF-8)
-- index 为【段内】自增序号 (每段从 0000 开始)
# Person
0000,Person,0,Name,小蝦米
0001,Person,0,Nick,天下奇男子
0002,Person,1,Name,胡斐
0003,Person,1,Nick,雪山飛狐
...
# Thing
0000,Thing,0,Name,大可樂
0001,Thing,0,Name2,大可樂
0002,Thing,0,Desc,活性飲料，迅速補充你的體力
...
# Scene
...
# Wugong
...
```

- **按段分组**：`# Person` / `# Thing` / `# Scene` / `# Wugong` 分节注释
- **index 列**：**段内**唯一（每段从 0000 开始），与 hint 中的数字对应
- **元信息列**（类别/记录/字段）：便于人工查阅与调试
- **值列**：UTF-8，保留繁体，**已去重**

**去重说明**：值相同则复用同一 index（**段内**共享）。
mingdong 实测：2724 字段 → 去重后 **1397 条**（重复率 49%），约 13KB。

> 去重仅在段内进行；跨段不共享（因旁路表本就按段分组）。
> 若希望跨段去重，可改用全局 index（代价是位数余量变小）。

## 3. Q-B 关键澄清：index 作 hint ≠ 不用保存旁路表

**旁路表必须保存。** hint 里只有 index（序号），**不含原始字符串**：

```
MOD 原始 ranger.grp (Big5)  ──构建期解码──►  旁路表 "胡斐"  ← 原始信息在这
                                            │
                          构建期把原字段替换成 "P0002"
                                            ▼
                    ranger.grp 字符串区 = "P0002"  ← 只剩 index，无原文
```

> **hint 是「指针」，旁路表是「被指向的数据」。指针不能替代数据。**

index 带来的好处是**结构更简单**（前缀 + 段内序号即唯一主键），
而不是「可以省略表」。

## 4. 存档：为什么仍需要 `rN.ovr`

玩家改名后，`rN.grp` 里 hint `P0000` 仍指向基础表的 `小蝦米`。要表达「本次存档是 郭靖」，
必须额外记录 `P0000 → 郭靖`。这就是 `rN.ovr`（本质是 index → 新值的覆盖表）。

### 能否不存 `rN.ovr`？（实测否决）

唯一办法是「存档里直接写真值而非 hint」。但实测样例 6 个 MOD：
**13061 条字符串中 5312 条（41%）UTF-8 超长，放不回原字段**（如 `雪山飛狐` 12 字节 > 10 字节字段）。
→ 会被截断 → **违反 Q3** → 不可行。

**结论：`rN.ovr` 必须存在。** 带段内 index 后它也变成简单两列：

```
mods/<slug>/save/r1.ovr
P0000=郭靖
S0008=郭靖居
```

（键自带段前缀，无需查表即知是哪个段；通常 0~2 行；未改名则为空文件。）

### 读取优先级

```
字符串 = rN.ovr[index] 有?  → 用它          (玩家改名等)
        : ranger.str[index] 有? → 用它      (99.9%)
        : 回退读 rN.grp 缓冲区              (原版/无 MOD，零回归)
```

## 5. 最终文件布局

```
mods/<slug>/data/ranger.grp   字符串区 = hint（P0000/N0001/T0005/...）；数值区一字不改
mods/<slug>/data/ranger.str   旁路表（UTF-8 去重，按段分组，含 index 列）
mods/<slug>/data/ranger.idx   原样复制

mods/<slug>/save/rN.grp       同布局；字符串区 = hint；数值区 = 玩家进度
mods/<slug>/save/rN.ovr       覆盖表（index=新值），通常空
```

文件大小：`ranger.grp` 不变（223688 → 223688）；新增 `ranger.str` ~13KB。
**截断：0（满足 Q3）。**

## 6. 零回归保证

| 场景 | 行为 |
|------|------|
| 未激活 MOD（原版） | 无 `ranger.str`/`rN.ovr` → 回退读缓冲区 → **原版行为完全不变** |
| 激活 MOD、未改名 | `rN.ovr` 空 → 全部走 `ranger.str` |
| 激活 MOD、改过名 | `rN.ovr` 只存那 1~2 条 |
| 跨 MOD | `data/` + `save/` 天然隔离（沿用 `ModData.Resolve`） |
