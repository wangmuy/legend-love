# battle-extensibility 实机验收清单

> 剩余 5 项任务全部是同一件事：**用眼睛看画面**。
> 自动化已经证明了「逻辑没变 + 零件在位 + 算法算得对 + 渲染链不崩」，
> 剩下的只有「画面对不对」。

## 前置

```bash
cd game && lua tests/test_runner.lua     # 应 3696/0
```

## 验收步骤（约 10 分钟）

### A. 手动战斗（最重要）

1. 启动游戏，进入主地图
2. 走到任一场景，触发一场战斗（或直接读一个战斗存档）
3. 依次验证：

| # | 操作 | 期望画面 |
|---|------|---------|
| A1 | 战斗开始 | 战斗地图正确显示（雪地/非雪地两种配色都试） |
| A2 | 我方回合 | 主角脚下有**蓝色可走范围**高亮（曼哈顿距离 ≤ 移动步数） |
| A3 | 移动光标 | 方向键移动光标时，路径高亮跟随 |
| A4 | 确认移动 | 人物走到目标格，**贴图朝向正确**（4 方向） |
| A5 | 攻击菜单 | 弹出「移动/攻击/用毒/解毒/医疗/物品/等待/状态/休息/自动」9 项 |
| A6 | 武功攻击 | 选择武功后，**攻击范围高亮**（点/线/十字/面 4 种类型） |
| A7 | 武功命中 | 播放武功效果动画（effect 贴图） |
| A8 | 伤害数字 | 敌人头上显示**红/黄/绿**伤害数字（颜色按受伤程度） |
| A9 | 头像 | 右上角显示战斗人物头像 + 生命/内力条 |
| A10 | 中毒 | 中毒的敌人每回合掉血，颜色变绿 |
| A11 | 敌人回合 | 敌方 AI 移动/攻击（**不应崩溃、不应卡住**） |

### B. 自动战斗

1. 战斗菜单选「自动」，或整场设为自动
2. 期望：AI 自动打完整场，**不卡在战斗画面**（这是历史上出现过的 bug）

### C. 战斗结算

| # | 期望 |
|---|------|
| C1 | 胜利后弹「XXX 获得经验点数 N」并等待按键 |
| C2 | 升级时弹「XXX 升级了」并等待按键 |
| C3 | 结算完回到主地图（**不应黑屏、不应卡在战斗画面**） |
| C4 | 战败时回到主地图（原版语义，不应弹"死亡画面"） |

## 重点怀疑区（如果出问题，优先查这些）

1. **战斗地图配色**：`WarDrawMap` 按 `WAR.Data["地图"]==0` 分雪地/非雪地。
2. **头像显示**：`WarShowHead` 走 `lib.PicGetXY` + `lib.PicLoadCache`，
   这两个在搬移后是**全局函数**（来自 `lib_love.lua`），不走 EngineAPI。
3. **武功效果**：`effect` 档案由 `SpriteAtlas.loadArchive(..., 3, ...)` 加载。
4. **结算等待**：`DrawStrBoxWaitKey` 现在走 `FlowFacade.drawStrBoxWaitKey`。

## 如果发现问题

把现象记下来（截图/描述），我来修。所有 66 个函数和 20 个协程都逐字节
等于改造前的版本，所以如果画面不对，**最可能是加载顺序或作用域**问题，
而不是逻辑问题 —— 这类问题通常表现为「调用时报 nil」或「某功能不生效」。
