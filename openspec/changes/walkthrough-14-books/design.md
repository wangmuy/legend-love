## Context

当前 `walkthrough-p1~p10` 测试已验证了 84 个场景中的大部分场景导航、NPC 招人、战斗等基础操作，但 14 天书的收集流程仅覆盖了 2 本（雪山飞狐、鸳鸯刀）。其余 12 本天书中有 11 本的事件脚本仍为 `--function` 注释状态，无法在游戏中触发。

## Goals / Non-Goals

**Goals:**
- 解锁 11 个天书相关 oldevent 脚本
- 为每本天书添加 e2e 测试验证（NPC 对话→获取天书）
- 验证圣堂放置天书事件（oldevent_1001~1014）
- 所有测试使用纯用户命令，零注入

**Non-Goals:**
- 实现条件触发系统（飞狐外传需胡斐+屠龙刀+金丝背心等组合条件）
- 光明顶倚天屠龙记完整剧情链（需多个场景联动）
- 最终十大高手战斗和通关动画的完整验证（oldevent_1015→1017 需收集全部14本天书后才能触发，依赖本 change 完成）

## Architecture Decision Records

### ADR-001: 新 change 而非修改现有 change

- **Context**: 14 天书收集是完整通关的必要步骤，但当前 walkthrough-main-quest 的 tasks.md 已全部标记完成。
- **Decision**: 创建新的子 change `walkthrough-14-books`，独立管理 14 天书收集的测试任务。
- **Consequences**: 任务边界清晰，现有已完成任务不受影响。

### ADR-002: 在原 P1-P10 测试文件中扩展而非创建新文件

- **Context**: 14 天书获取步骤分散在 P1-P10 的各个场景中，需要按场景顺序插入。
- **Decision**: 在现有 walkthrough-p1~p10 测试文件中添加天书获取验证步骤，不创建新文件。
- **Consequences**: 测试架构不变，现有存档跳转链无需调整。

### ADR-003: 天书事件脚本直接解锁

- **Context**: 11 个天书相关 oldevent 脚本被注释（`--function`），原因为部分事件依赖条件触发系统。
- **Decision**: 直接解锁脚本（取消注释），让基本 NPC 对话流程可执行。条件触发逻辑（如飞狐外传的复合条件）作为后续改进。
- **Consequences**: 脚本可被触发，即使条件不满足也能显示对话，不会 block 用户。

## 测试策略

### 天书获取测试模式
每个天书场景采用相同的测试模式：
1. `loadTestState(slot)` — 从存档恢复
2. `gotoScene(sceneName)` — 导航到场景
3. `look` — 查看 NPC/事件列表
4. `choose N` — 选择对应的 NPC 或 tile event
5. `choose 1` — 对话/触发
6. 验证终端输出包含天书名称或对话文本
7. `saveTestState(slot)` — 保存进度

### 存档跳转链
```
P1(slot 11~16) → P2(slot 21~22) → P3(slot 31~32) → P4(slot 41~42)
  → P5(slot 51~53) → P6(slot 61~63) → P7(slot 71~72)
  → P8(slot 81) → P9(slot 91) → P10(slot 101)
```
