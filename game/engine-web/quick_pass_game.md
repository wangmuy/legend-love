# 金庸群侠传 Web MUD - 完整通关操作手册

本文档记录从开局到通关的完整用户操作流程，对应 `walkthrough-p1~p10` 自动化测试。
每个步骤均为纯用户命令（`leave`/`list`/`look`/`choose <N>`），可在终端中手动验证。

---

## 操作说明

- `choose N` — 选择菜单项/交互对象/对话选项
- `list` — 在大地图列出可去场景（按名称排序，编号固定，见下方「大地图场景编号表」）
- `leave` — 离开当前场景返回大地图
- `look` — 手动重新查看当前场景列表/战场态势（可选：进入场景后列表自动显示，一般无需输入；需要刷新时使用）
- `menu` — 打开主选单（医疗/解毒/状态/物品/队伍/存档/踢人）
- `help` — 显示帮助

> **交互行为说明**（与实际 MUD 行为对齐）：
> - 进入场景后**自动显示**交互对象列表，无需输入 `look`
> - `choose <NPC>` 后**直接开始对话**（无需 `choose 0` 打开对话框）；对话显示完后**自动返回**场景列表
> - 事件/战斗/物品使用结束后也**自动重新显示**场景列表
> - 攻略步骤中不再需要手输 `look` 或 `choose 0 关闭对话框`；`look` 指令仍保留，仅作手动刷新查看之用
> - **搜索实体显示稳定事件 id**：`搜索[oldevent_XXX]`（如 `搜索[oldevent_879]`）——取走物品后列表会收缩、编号会变化，按 id 即可对上攻略中的 `choose`（如攻略写 `oldevent_879` 就选显示为 `搜索[oldevent_879]` 的那一行）；放置天书显示为 `放置天书[1XXX]`

### gotoScene 自动导航流程

```
leave           ← 回到大地图
list            ← 列出可去场景（按名称排序）
choose <编号>   ← 按「大地图场景编号表」的编号导航（固定编号，见文末附表）
```

### 验证清单（手动操作时可对照）

- 南贤居 → 显示"一间普通的民居"（非客栈）
- 田伯光居 → 只搜索鸳刀，不招田伯光（避免道德-6，保证狄云可加入）
- 闫基战斗 → 战斗胜利后显示获奖信息
- 各场景描述应与场景类型匹配（民居/山洞/客栈等）

### 存档操作说明

通过 `menu` 主选单进行存档/读档，使用纯用户命令：
- `menu` → `choose 6` → `choose N`（存到槽位 N，N=1~10）
- `menu` → `choose 6` → `choose N+10`（读取槽位 N，如 choose 11=读取槽位1）
- 存档时先 `menu` 打开主选单，选"6. 系统（存档/读档）"，再选槽位
- 读档时同样进入系统菜单，选对应读取选项

## 场景 look 列表重复项说明

**检查方法**: 复刻 `SmapHandlers.look` 实体列表生成逻辑（`scripts/check_scene_dupes.js`），
静态计算全部 84 个小场景**首次进入**时的 look 内容列表，检测重复项。检查对象含用户点名的
开局主角居（scene 70）、絕情谷（scene 22）、冰蠶洞（scene 66）——三者均**无任何重复项**。
全量结论（显示层去重修复后）：仅 18/84 场景存在重复项，均为"数据本身如此"，分两类：

### 1. 数据本身如此（正常，不是问题）

- **同名场景**: 4 个"山洞"（scene 5/41/65/79），攻略已按坐标区分（唐诗山东=scene 65）
- **多出口同目标**: 明教分舵/沙漠废墟/梅庄/崑崙仙境/霹雳堂 各有 3 个出口指向同一场景，
  原版数据即为多出口
- **同事件多 tile**: 如大轮寺钥匙孔(oldevent_598)在 tile 6/7 都有 eventTouch → 显示 2 个"搜索"
- **物品列表**: 0 个场景存在物品重复

### 2. 显示层重复（已修复：look() 跨段去重）

原 D* 表（`JY.D[sceneId]` 由 events.json 初始化）扫描与 events.json grid 扫描**同时**列出同一事件，
导致同一"搜索"出现 2 次（如大轮寺 596、苗人凤居 30/7、蜘蛛洞 375~380、圣堂天书事件等，共 69 处）。
圣堂天书事件尤为明显：每个天书位同时显示"搜索"（D* 扫描）与"放置天书"（grid 扫描）。

**已在 `mmap_smap_handlers.lua` 的 `look()` 中修复**（脚本 `scripts/check_scene_dupes.js` 同步更新）：
- 静态 NPC / D* 扫描 / 入口事件已列出的事件号，grid 格子事件段不再重复显示（同一事件全列表只显示一次）
- 天书放置事件（1001~1014）改由 grid 段以"放置天书"列出（不再显示多余的"搜索"）
- 修复后 DISPLAY_DUP 全部消除，仅剩"数据本身如此"的 DATA_DUP 17 处（同事件多 tile，13 场景）
  与 EXIT_DUP 5 处（多出口同目标，5 场景），均属原版数据，列表逐格列出属预期；
  walkthrough p1~p10 回归验证全绿
